# QA Game — корпоративный конкурс по поиску багов

Статическое приложение для GitHub Pages: участники ищут дефекты на витрине
магазина спортивных товаров «СпортАрена», описывают их прямо в интерфейсе, а организатор
через админку видит, кто участвовал, что нашёл, за какое время, и проставляет вердикты.

Ни сервера, ни базы данных: хранилище — приватная Google-таблица, к которой
приложение обращается через Google Apps Script. Если бэкенд не настроен,
приложение работает офлайн и обменивается результатами через текстовые коды.

## Ход конкурса: раунды

Конкурс состоит из раундов, которыми управляет организатор. **Дефекты принимаются
только пока раунд идёт** — до старта и после закрытия поле ввода заблокировано.

В админке есть карточка «Управление раундом»:

| Действие | Что происходит |
| --- | --- |
| **Начать раунд N** | открывается приём дефектов; можно задать название и длительность (0 — без таймера, закроется вручную) |
| **Завершить раунд** | приём немедленно прекращается у всех участников |
| **Новый конкурс** | удаляет всех участников, дефекты и вердикты, нумерация раундов обнуляется |

Новый раунд обнуляет прогресс участника: счётчик и список начинаются заново, а
находки прошлых раундов остаются у организатора и доступны через фильтр по раунду.

**Игра начинается для всех одновременно.** До старта витрина закрыта оверлеем и
размыта — тот, кто вошёл за полчаса до начала, не успеет изучить каталог заранее.
Отсчёт времени идёт от старта раунда, а не от входа. Оверлей снимается сам, без
перезагрузки страницы; после закрытия раунда он возвращается.

Чтобы разброс на старте был минимальным, участник спрашивает состояние раунда чаще,
пока ждёт (`roundPollWaitingMs`, по умолчанию 4 секунды), реже во время раунда и
почти не спрашивает в скрытой вкладке. Если ожидание перед стартом долгое, а
участников много, увеличьте этот интервал — ценой нескольких секунд разброса.

### Если кто-то снимет оверлей

Витрину нельзя закрыть по-настоящему: код исполняется в браузере участника, и
`class="blur-[14px]"` удаляется через инструменты разработчика в один клик. Помешать
этому со статики невозможно, поэтому сделано так, чтобы заглянувший себя выдал.

**Отметка в админке.** Приложение следит за обёрткой витрины: снятие размытия,
удаление заглушки или клик по товару сквозь оверлей ставят участнику флаг, который
уходит на сервер вместе с прогрессом. В лидерборде появляется колонка «Честность»
с пометкой «заглядывал», снять её клиент не может — сервер отметку не затирает.
Ложных срабатываний на старте раунда нет: там размытие убирает сам React, и это
поведение учтено.

**Приманка.** Пока витрина закрыта, на баннере показаны промокоды `PEEK50` и
`GHOST99`. В работающем магазине их не существует. Если такой код всплывёт в
баг-репорте — участник не просто посмотрел, а попробовал применить код, получил
«Промокод не найден» и завёл на это дефект. Админка подсвечивает такие репорты
отдельной плашкой.

В отчёте по итогам раунда обе проверки сводятся в номинацию **🕵️ Любопытный** — её
можно зачитать в шутку, а можно использовать всерьёз.

> **Важное ограничение статики.** Общее для всех состояние раунда возможно только
> с настроенным Apps Script: страница на GitHub Pages не может ничего разослать в
> чужие браузеры сама. С endpoint участники узнают о старте и закрытии в течение
> 10 секунд, а сервер дополнительно **отклоняет** дефекты, заведённые вне раунда, —
> обойти блокировку через консоль не выйдет. Без endpoint раунд управляется только
> в браузере организатора, и запрет держится честностью участников.

### Демо-режим

Для показа коллегам поставьте `requireLogin: false` в [`src/config.ts`](./src/config.ts):
вход отключается, приложение открывается сразу под гостевым логином, а в шапке
появляется кнопка перехода в админку без пароля.

## Что внутри

| Роль | Вход | Что делает |
| --- | --- | --- |
| Участник | только имя или корпоративный логин, без пароля | тестирует магазин, заводит баг-репорты, видит статус и таймер раунда |
| Организатор | логин + пароль | управление раундами, лидерборд, валидация, авторазбор, эталонный список, выгрузка CSV |

Стартовая страница показывает правила конкурса, шкалу баллов, разделы для поиска и
текущее состояние раунда — участник видит его ещё до входа.

Тренажёр — витрина магазина спортивных товаров: баннер акции, категории, карточки
товаров с рейтингом и отзывами, избранное, быстрый просмотр, корзина со сводкой
заказа и оформление в три шага с выбором доставки и оплаты.

Заложено **39 дефектов** в каталоге, корзине, оформлении заказа и
вёрстке — от опечаток до блокирующих ошибок расчёта. Полный перечень с подсказками
доступен админу по кнопке «Эталонный список» (лежит в отдельном чанке, в бандл
участника не попадает).

Дефект заводится **одной строкой**: поле ввода закреплено в шапке, участник пишет,
что сломалось, и жмёт Enter. Ни серьёзность, ни раздел указывать не нужно —
это замедляло участников и ничего не давало, потому что баллы всё равно
начисляются по серьёзности эталонного дефекта, а не по самооценке.

Кнопка «Подробно» открывает полную форму с шагами воспроизведения, ожидаемым и
фактическим результатом; она же подхватывает уже набранный текст. Дописать детали
можно и позже — карандашом в списке «Мои дефекты». Для каждого репорта фиксируется
время от старта раунда, по нему видно скорость участника.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
```

## Публикация на GitHub Pages

1. **Settings → Pages → Source: GitHub Actions**.
2. Push в `main` — workflow `.github/workflows/deploy.yml` соберёт и опубликует проект.
   `VITE_BASE` подставляется автоматически из имени репозитория.
3. Приложение доступно по адресу `https://<owner>.github.io/<repo>/`.

Для публичных репозиториев Pages бесплатны. Платный план нужен только чтобы
опубликовать сайт из **приватного** репозитория.

## Другие бесплатные хостинги

Сборка — обычная статика в `dist/`, поэтому подойдёт любой статический хостинг. Везде ниже
достаточно указать команду `npm run build` и каталог `dist`, а `VITE_BASE`
**не задавать**: эти площадки отдают сайт из корня домена, в отличие от GitHub Pages.

| Хостинг | Как развернуть | Бесплатный лимит |
| --- | --- | --- |
| **Cloudflare Pages** | подключить репозиторий, framework preset *Vite* | безлимитный трафик, 500 сборок/мес |
| **Netlify** | подключить репозиторий, настройки возьмутся из `netlify.toml` | 100 ГБ трафика, 300 мин сборки/мес |
| **Vercel** | `Add New → Project`, Vite определяется автоматически | 100 ГБ трафика/мес |

Любого из них хватает на 100 участников с запасом: приложение раздаёт ~65 КБ gzip
и после загрузки работает без обращений к серверу.

Разложить сборку можно и вручную — например, отдать `dist/` с любого внутреннего
веб-сервера компании:

```bash
npm run build   # результат в dist/
```

## Сбор результатов: приватная Google-таблица

Пошаговая инструкция — [`google-apps-script/README.md`](./google-apps-script/README.md).
Коротко:

1. Создать Google-таблицу и вставить в её Apps Script файл `Code.gs`.
2. В свойствах скрипта задать `ADMIN_PASSWORD`.
3. Опубликовать как веб-приложение («от имени: я», «доступ: у всех»).
4. Прописать полученный URL в `syncEndpoint` в [`src/config.ts`](./src/config.ts).

Таблица остаётся приватной: участники обращаются к веб-приложению, а не к документу,
и прав на него не получают. Пароль администратора хранится на стороне Google
и в собранный фронтенд не попадает.

Клиент отправляет накопленные репорты раз в 20 секунд, при закрытии вкладки и при
нажатии «Завершить». Отправка идемпотентна (upsert по id репорта), запись идёт под
`LockService`, поэтому 100 параллельных участников таблицу не портят.

### Если бэкенд не настроен

Приложение работает офлайн: репорты лежат в `localStorage`, по кнопке «Завершить»
участник получает код результата и передаёт его организатору. В админке — «Импорт
кода», можно вставить сразу несколько кодов, по одному в строке.

Офлайн-режим полезен и как страховка: если Apps Script вдруг недоступен, участник
ничего не теряет — код результата выдаётся в том же окне завершения.

## Настройка конкурса

Всё в [`src/config.ts`](./src/config.ts):

| Параметр | Назначение |
| --- | --- |
| `title` | название конкурса в шапке |
| `requireLogin` | `false` — демо-режим без входа; `true` — боевой режим с логинами |
| `syncEndpoint` | URL веб-приложения Apps Script; пусто → офлайн-режим |
| `adminLogin` | логин администратора |
| `adminPasswordSha256` | SHA-256 пароля, **только** для офлайн-режима (по умолчанию `qa-admin-2026`) |
| `allowedLoginSuffixes` | ограничение логинов, например `['@company.ru']` |
| `roundMinutes` | длительность раунда, `0` — без таймера |
| `syncIntervalMs` | период автосохранения |
| `roundPollWaitingMs` | как часто участник проверяет старт раунда, пока витрина закрыта |
| `roundPollRunningMs` | то же во время раунда |
| `roundPollHiddenMs` | то же в скрытой вкладке |

Новый хэш пароля для офлайн-режима:

```bash
printf 'новый-пароль' | sha256sum
```

> В офлайн-режиме хэш лежит в статике и подбирается перебором — он защищает от
> случайного захода, а не от целенаправленного взлома. Когда `syncEndpoint` задан,
> пароль проверяется на стороне Google и в бандле его нет вообще.

## Авторазбор: не отсматривать сотни репортов руками

Кнопка **«Авторазбор»** в админке сопоставляет каждый репорт с эталонным списком
по ключевым словам. У каждого дефекта заданы группы слов: первая называет объект
(«промокод», «сортировка», «CVV»), вторая — суть проблемы («многократно»,
«как строки», «открытым текстом»). Совпадение считается уверенным, только когда
сработали **все** группы: одного слова «корзина» мало, оно есть в половине репортов.

После разбора появляется сводка и три действия:

- **«Принять уверенные»** — массово подтверждает распознанные находки. Баллы берутся
  по серьёзности эталонного дефекта, а не по той, что проставил участник, — иначе
  оценки поехали бы от того, кто щедрее к себе.
- **«Пометить дубликаты»** — второй и последующий репорты одного участника про тот же
  дефект уходят в «Дубликат» с нулём баллов. Первая находка засчитывается.
- **«Покрытие»** — в эталонном списке видно, какие дефекты нашли и кто именно,
  а какие не нашёл никто.

Фильтры «уверенно / нужен взгляд / не распознано / повторы» позволяют сразу открыть
ту стопку, которая требует глаз. У каждого репорта в списке видно найденный код,
а во всплывающей подсказке — какие именно слова сработали, чтобы решение автомата
можно было проверить.

**Автомат ничего не отклоняет.** Он либо уверенно принимает, либо помечает повтор,
либо оставляет репорт вам. Это осознанный компромисс: ложно приписать дефект чужому
коду хуже, чем показать его человеку.

### Качество распознавания

Точность закреплена тестом — `npm run check:matcher`, он же выполняется при `npm run build`.
Набор из 79 формулировок «как пишет живой участник», включая нарочно кривые и путающие
похожие дефекты: **78 уверенных попаданий, ноль неверных кодов**, мусор вроде «что-то не
работает» отсеивается. Сборка падает, если появится хоть один неверный код или точность
опустится ниже 90 % — так правка эталонного списка не сломает разбор незаметно.

Если меняете дефекты, правьте и `keywords` в [`src/lib/knownBugs.ts`](./src/lib/knownBugs.ts),
а тестовые формулировки — в [`scripts/check-matcher.ts`](./scripts/check-matcher.ts).

## Итоги раунда

Кнопка **«Итоги раунда»** в админке собирает отчёт для объявления результатов.
Считается только по подтверждённым находкам, поэтому смотреть его стоит после
разбора — если что-то ещё в очереди, отчёт об этом предупредит.

Обязательные рубрики:

- **⚡ Самая быстрая находка** — кто и на какой минуте от старта завёл первый
  засчитанный дефект;
- **👀 Самый заметный дефект** — что нашло больше всего участников;
- **💎 Самая редкая находка** — дефект, который заметил ровно один человек;
- **Не нашёл никто** — список пропущенных, его хорошо зачитывать в конце.

И шуточные номинации, которые появляются, только если для них набрались данные:

| Номинация | За что |
| --- | --- |
| 🎯 Пулемётчик | больше всего подтверждённых находок |
| 🔍 Снайпер | лучшая доля попаданий (от трёх заявок) |
| 🧭 Первопроходец | больше всего дефектов, которых не увидел никто другой |
| 💰 Джекпот | самая дорогая единичная находка |
| 🏁 На последнем дыхании | последняя засчитанная находка раунда |
| 📜 Летописец | самый длинный заголовок |
| ✂️ Телеграфный стиль | самый короткий заголовок |
| 🔁 Эхо | больше всего собственных повторов |

Кнопка «Скопировать для чата» отдаёт отчёт простым текстом — можно сразу отправить
в общий канал.

### Личные итоги у участников

Кнопка **«Опубликовать участникам»** в том же окне отправляет итоги на сервер, и
у каждого участника вместо витрины появляется его личный экран:

- место и сумма баллов, медаль за первые три места;
- сколько находок засчитано, сколько отклонено, сколько нашёл он один и на какой
  минуте была первая засчитанная;
- **его** номинации — те, где он победитель;
- разбор всех его находок: статус, баллы и комментарий валидатора;
- общая таблица (первая десятка плюс своя строка, если участник ниже) и список
  того, что не нашёл никто;
- кнопка «Скопировать мои итоги» — короткий текст для чата.

Публиковать можно сколько угодно раз: каждая публикация перезаписывает предыдущую,
так что после правки вердиктов достаточно нажать кнопку ещё раз. Считаются итоги
в админке — только у неё есть эталонный список, — а сервер их лишь хранит и
раздаёт. Подсказки и ключевые слова эталонных дефектов в опубликованные итоги не
попадают, номинация 🕵️ «Любопытный» тоже: называть подглядывавших публично или нет,
решает организатор.

До публикации участник видит обычную заглушку «Раунд завершён» — экран итогов не
появляется сам по себе.

## Подсчёт баллов

Баллы определяются серьёзностью **эталонного** дефекта, на который указал разбор:
блокирующий — 10, критический — 8, значительный — 5, незначительный — 3,
тривиальный — 1. Участник серьёзность не указывает, так что накрутить оценку
своей находке нельзя. Если разбор ничего не нашёл, значение проставляет валидатор
в поле рядом с кнопками вердикта. Лидерборд считает сумму баллов только по принятым
дефектам; дубликаты и отклонённые дают 0.

Список дефектов открывается как **очередь разбора**: неразобранные находки всех
участников одним списком, после вердикта карточка уходит из очереди. Если ошиблись,
рядом появляется «Вернуть на проверку».

## Как проводить конкурс

1. Настроить Apps Script и `syncEndpoint`, задеплоить, проверить вход организатором.
2. Раздать участникам ссылку заранее: они прочитают правила и войдут по имени.
   Пока раунд не начат, ввод заблокирован — магазин можно спокойно изучать.
3. Нажать «Начать раунд», задать название и длительность.
4. Следить за ходом в админке (кнопка «Обновить»).
5. «Завершить раунд» — приём закрывается у всех.
6. «Авторазбор» → «Принять уверенные» → «Пометить дубликаты», глазами пройти только
   стопки «нужен взгляд» и «не распознано». Выгрузить CSV.
7. Следующий поток — снова «Начать раунд». Совсем новый конкурс — «Новый конкурс».

Без шага 1 конкурс тоже проводится, но каждый участник играет изолированно, раунд
у него локальный, а результат передаётся организатору кодом вручную.

## Стек

React 18, TypeScript, Vite, Tailwind CSS, lucide-react. Внешних сервисов, кроме
вашего Apps Script, приложение не использует.
