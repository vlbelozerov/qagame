# Бэкенд на Google Apps Script (10 минут)

Результаты участников складываются в **вашу приватную Google-таблицу**. Никто, кроме
владельца документа, её не видит: страница на GitHub Pages обращается не к таблице,
а к веб-приложению, которое выполняется от вашего имени.

## 1. Создайте таблицу

Создайте пустую Google-таблицу, например «QA Game — результаты». Листы `reports`,
`participants` и `state` скрипт создаст сам при первом запросе.

## 2. Добавьте скрипт

В таблице: **Расширения → Apps Script**. Удалите содержимое `Код.gs` и вставьте
[`Code.gs`](./Code.gs) из этой папки. Сохраните.

## 3. Добавьте эталонный список

Сначала соберите файл у себя:

```bash
QAGAME_SECRET="пароль от списка" npm run build:reference
```

Команда создаст `google-apps-script/Reference.gs`. В репозитории его нет: он публичный,
а этот файл — ответы, все заложенные дефекты с подсказками. В git список хранится
только зашифрованным (`secret/known-bugs.enc`).

Затем в редакторе Apps Script: **＋ рядом с «Файлы» → Скрипт**, назовите файл
`Reference` и вставьте содержимое собранного файла. Сохраните.

Сервер отдаёт список только по паролю организатора — в браузер участника он не
попадает вовсе. После правок дефектов пересоберите файл той же командой и вставьте
заново.

## 4. Задайте пароль администратора

В редакторе Apps Script: **⚙ Настройки проекта → Свойства скрипта → Добавить свойство**.

| Свойство | Значение |
| --- | --- |
| `ADMIN_PASSWORD` | пароль администратора конкурса |
| `ADMIN_LOGIN` | необязательно, по умолчанию `admin` |

Пароль хранится на стороне Google и в собранный фронтенд не попадает.

## 5. Опубликуйте веб-приложение

**Начать развёртывание → Новое развёртывание → Тип: веб-приложение**:

- «Запуск от имени» — **я** (владелец таблицы);
- «У кого есть доступ» — **у всех**.

Подтвердите запрошенные разрешения. Скопируйте URL вида
`https://script.google.com/macros/s/AKfy.../exec`.

> «У всех» открывает доступ к веб-приложению, а не к таблице. Записывать данные сможет
> любой, кто знает URL, а читать сводку и ставить вердикты — только тот, кто знает
> `ADMIN_PASSWORD`.

## 6. Пропишите URL во фронтенде

В `src/config.ts`:

```ts
syncEndpoint: 'https://script.google.com/macros/s/AKfy.../exec',
```

Закоммитьте и запушьте — GitHub Actions пересоберёт и обновит страницу.

## Проверка

Откройте URL развёртывания в браузере — ответ показывает, что именно развёрнуто:

```json
{"ok":true,"result":{
  "service":"qagame","status":"ready","version":"2026-09-08",
  "reference":39,
  "actions":["submit","round","results","adminLogin","adminSnapshot","adminVerdict",
             "adminStartRound","adminFinishRound","adminReset","adminPublishResults","adminReference"]}}
```

На что смотреть:

| Поле | Что означает |
| --- | --- |
| `version` | дата версии скрипта; отличается от текущей — развёрнут старый код |
| `reference` | сколько дефектов в эталонном списке; `нет файла Reference.gs` — список не добавлен |
| `actions` | доступные действия; нет `adminReference` — развёртывание старое |

Ответа нет вовсе или он не JSON — проверьте, что развёртывание опубликовано с
доступом «у всех».

## Что даёт бэкенд помимо хранения

Лист `state` хранит состояние игры, общее для всех участников. Благодаря ему:

- эталонный список дефектов хранится здесь и уходит в админку только после проверки
  пароля — в собранном сайте его нет, из инструментов разработчика его не достать;
- организатор запускает и завершает игру для всех сразу, участники узнают об этом
  в течение 10 секунд;
- сервер **отклоняет** дефекты, заведённые вне игры или относящиеся к прошлому
  запуску, — блокировку в интерфейсе нельзя обойти через консоль браузера;
- кнопка «Новый конкурс» очищает листы `reports`, `participants`, `results` и
  обнуляет счётчик запусков.

Лист `results` появляется сам при первой публикации итогов и хранит их готовым
JSON: участники забирают его одним запросом. Длинные итоги режутся на куски по
40 000 символов (в ячейку Sheets влезает 50 000) и склеиваются при чтении.

> Если вы уже запускали более раннюю версию скрипта, удалите старые листы `reports`
> и `participants` перед обновлением: в них добавилась колонка `round`, и порядок
> столбцов изменился.
>
> Колонка `bugCode` (код эталонного дефекта, проставленный при разборе) дописывается
> в лист `reports` автоматически при первом обращении — удалять и пересоздавать листы
> не нужно, данные прошлых запусков сохранятся.
>
> После любого обновления `Code.gs` **создавайте новое развёртывание** (Развернуть →
> Управление развёртываниями → карандаш → Версия: новая). Без этого сайт продолжит
> обращаться к старому коду, и новые действия — например, публикация итогов —
> вернут ошибку «Неизвестное действие».

## Ограничения и нагрузка

- Суточной квоты на вызовы веб-приложения Google не публикует: 20 000 в сутки — это
  лимит на `UrlFetch`, то есть на исходящие запросы самого скрипта, а их здесь нет.
  Реально ограничивают 30 одновременных выполнений и 6 минут на одно выполнение —
  ни в то, ни в другое конкурс не упирается.
- Настоящее узкое место — общая блокировка скрипта: она одна на весь проект, и её
  ждёт не только приём находок, но и запуск игры. Поэтому под блокировкой в
  `handleSubmit` идёт только запись: состояние игры читается до неё, а строки
  участника — после и лишь когда клиент их попросил (`wantVerdicts`).
- Со стороны клиента находка уходит сразу, а пустая отметка «я здесь» — не чаще
  `heartbeatMs` (60 секунд). Раньше клиент слал обмен каждые 20 секунд даже на
  экране ожидания, и полутора десятков вкладок хватало, чтобы запуск игры упал
  с «таймаутом блокировки».
- Если организатор всё же поймал «Сервер занят записью данных участников» —
  просто повторите действие: очередь разгребается за секунды.
- Если бэкенд недоступен, участник ничего не теряет: репорты лежат в его браузере,
  а по кнопке «Завершить» выдаётся код результата для ручной передачи организатору.
